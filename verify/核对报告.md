## 3. 四处错误的证据

### 3.1 「SMOTE 把原先零召回的少数类提升到 0.19–0.41」

同一份数据、同一个划分（`random_state=42`），只改「是否 SMOTE」：

| 类别 | 测试样本 | 不做 SMOTE 的 LR 召回 | LR + SMOTE 召回 |
|---|---:|---:|---:|
| anger | 22 | 0.0000 | **0.0000** |
| boredom | 36 | 0.0000 | 0.2222 |
| enthusiasm | 152 | 0.0000 | 0.0724 |
| fun | 355 | 0.0113 | 0.2000 |
| happiness | 1042 | 0.3503 | **0.3186** ↓ |
| hate | 265 | 0.0830 | 0.3208 |
| love | 768 | 0.3607 | 0.4128 |
| neutral | 1727 | 0.6016 | 0.2096 ↓ |
| relief | 305 | 0.0098 | 0.1836 |
| sadness | 1033 | 0.2033 | 0.2749 |
| surprise | 437 | 0.0229 | 0.1442 |
| worry | 1692 | 0.4911 | 0.3067 |
| **整体准确率** | 7834 | **0.3524** | **0.2691** |
| **Macro-F1** | | 0.1746 | 0.2038 |

问题有三层：

1. `love`（0.36）和 `happiness`（0.35）**本来就不是零召回**，把 0.41 说成「从 0 提升」不成立；`happiness` 实际还降了 3.2 个百分点。
2. 真正零召回的 `anger` 在 SMOTE 之后**仍然是 0**（22 个测试样本全部预测错），`enthusiasm` 也只有 0.07。
3. SMOTE 的代价被完全隐去：整体准确率从 0.3524 掉到 0.2691，比 MNB 基线（0.3171）还低 4.8 个百分点。SMOTE 换来的是 Macro-F1 从 0.1746 → 0.2038（+0.029）和长尾类召回。

**建议改法**（二选一）：

> SMOTE 后长尾类召回明显提升：boredom 0→0.22、fun 0.01→0.20、hate 0.08→0.32、love 0.36→0.41，Macro-F1 由 0.17 升至 0.20；代价是整体准确率由 0.35 降至 0.27，且样本仅 22 条的 anger 仍为 0。因此把 SMOTE 定位为「牺牲整体准确率换长尾召回」的方案。

### 3.2 「词级归因分数 +0.87 / −0.96」

可查到的全部证据：

| 来源 | amazing | sucks | stupid |
|---|---:|---:|---:|
| `notebooks/01_eda_tfidf.ipynb`（LR C=1.0，class_weight=balanced） | +3.7338 | −3.6326 | — |
| 本次重跑（与提交代码一致的 C=0.5） | +2.9343 | −2.8540 | −2.0583（排名 9985/10000） |
| 素材库 | **+0.87** | **−0.96** | 称为高权重词 |

`+0.87 / −0.96` 既不是系数、也不是归一化后的系数（归一化后应落在 ±1 内且比例不变，而这里 3.73/−3.63 ≈ 1.03，不是 0.87/−0.96 的关系）。**建议直接换成真实系数，或删掉具体小数。**

### 3.3 「最终方案准确率与 F1 均稳定在 80% 以上」

- 二分类：冻结 79.40%、微调 0.8053，成立。
- 12 类多分类：MNB 0.32、LR+SMOTE 0.27，Macro-F1 0.13–0.20，**离 80% 很远**。

素材库括号里已经写了「正负向情绪的二分类任务」，但结论句又回到「最终方案」，容易被面试官理解成 13 类也有 80%。建议明确写「二分类任务上」。

### 3.4 「正则过滤 @ 提及」

```python
re.sub(r"@[\\w]*", "", "@dannycastillo We want...")  # -> "dannycastillo We want..."
```

`[\\w]` 在正则里是「`\` 或 `w`」的字符集合，不是「单词字符」。正确写法是 `@\w+`（或 `@\S+`）。这个 bug 不影响最终准确率（用户名本身也是弱信号），但「过滤 @ 提及」的描述与代码不符。

### 3.5 关于 80.76% 这个数（可复现，但要会解释）

本次微调三个 epoch 的 eval accuracy 分别是 **0.8066 / 0.8076 / 0.8053**，最终模型（第 3 epoch）为 **80.53%**。
素材库写的 80.76% 恰好等于第 2 个 epoch 的 eval 值，推测原记录取的是这一轮（best epoch）。

两者只差 0.23pp，Weighted F1 0.81、AUC 0.88（实测 0.8771）也都对得上，**这一条不算错**。但面试口述时建议说「约 80.5%」，被追问再解释「第 2 轮 best 是 80.76%，第 3 轮略回落」。
